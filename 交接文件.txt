一、项目定位
----------------------------------------
为 Android 5（minSdk 21）打造的多供应商 AI 聊天助手，基于 numAi
（github.com/gohoski/numAi，Android 1.0+ 的 LLM 客户端）的架构蓝本重制。
三大核心卖点：
  1. 思考等级四档：Low / Default / High / MAX（聊天界面实时切换）
  2. 多供应商多模型：A=DeepSeek、B=Claude+GPT、C=Qwen，
     一段对话中不同消息可用不同供应商的模型（如识图用 B 的 Claude、简单问答用 A 的 ds）
  3. 视觉识图：OpenAI 标准 content 数组 + image_url base64

二、已确定的需求决策（与用户对齐）
----------------------------------------
  1. 供应商接入：全部走 OpenAI 兼容中转（NewAPI 等），一个 baseUrl 一套 key；
     Claude 也经中转以 OpenAI 格式调用，客户端不写 Anthropic 适配层。
  2. 思考等级：统一抽象四档，映射 reasoning_effort；不支持思考等级的模型直接忽略。
  3. 模型切换作用域（用户给的规格）：
     - 默认模型 + 发送时锁定 + 下一回合可切换
     - 日常聊天用默认模型，不强制每次选择
     - 发送前可临时切换；发送瞬间锁定到当前执行回合
     - 回合内（含工具调用多步）沿用锁定模型；回合结束后下一条可再切
     - 临时切换不修改全局默认模型
     - 历史每条 assistant 消息记录实际用的 provider+model+thinkingLevel
     - UI：输入栏紧凑模型选择器，显示供应商/模型名/默认或临时状态/下拉箭头；
       菜单或选择器内可"设为默认"；默认模型带视觉标识；持久化到 SharedPreferences
  4. 视觉识图：必须支持（用户明确纠正过"先不做"的错误选择）。
  5. 依赖策略：代理决定，要求占用存储小 + 尽量美观。

  A6 历史图片占位：仅当前回合 user 消息带 base64；更早历史替换 [图片] 占位；

  B1 中转兼容双模式：默认统一 reasoning_effort；setting 有 newapiDialect 开关（已实现）。

五、明天第一步：补写 MainActivity.java（唯一缺失的核心 Java）
----------------------------------------
文件位置：app/src/main/java/io/github/numai5/MainActivity.java
关键设计（务必按此实现）：
  a) 状态机四变量 + 回合锁定：
       defaultModel：来自 ConfigManager（持久化），不可直接改
       pendingModel/pendingLevel：当前待发送选择（启动时 pending=default）
       lockedModel/lockedLevel：发送瞬间锁定，回合内不变
     发送流程：lockedModel=pendingModel → ApiService.chatCompletion(...,
     lockedModel, lockedLevel) → 回合结束(onSuccess/onError)清 locked；
     pending 保持用户选择（临时切换不回默认，符合"下一条可切换"）。
  b) 流式 UI 刷新：ApiService 在后台线程填 Message.content/reasoningRaw，
     MainActivity 用 Handler.postDelayed 每 200ms 轮询 currentAssistantMsg
     内容长度变化，有变化才 adapter.notifyItemChanged(最后一项)+scrollToBottom；
     回合结束/失败时停止轮询；断流时消息 isError 显示"生成中断"并保留已收内容。
  c) 只要锁定模型 supportsThinking，UI 尊重其 effortDialect；四档通过
     ThinkingMapper.apply(level, model.effortDialect) 转换（ApiService 已做）。
  d) 图片选择：btnImage → 菜单(相册/拍照)；onActivityResult 调
     ImagePicker.onActivityResult(...) 得文件名，加入 pendingImages；
     发送时文件名列表附给当前 user 消息（ApiService 负责当回合 base64、历史占位）。
     非视觉模型时点击图片提示"当前模型不支持视觉"。
  e) 菜单（res/menu/menu_main.xml，待建）：新对话、历史、设置、
     把当前 pendingModel 设为默认、关于。
  f) onResume 刷新配置变化（设置页改默认模型后回来要生效）。
  g) 发送前检查 ConfigManager.isValid()，无效 toast 提示去设置。
